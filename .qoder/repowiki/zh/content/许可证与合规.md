## 简介

Flower Age Video（花纪视频工作室）是一个AI驱动的无限画布创意工作站，专注于为视频创作者、内容生产者和AI艺术家提供本地化的桌面应用解决方案。该项目在设计上明确承诺100%采用MIT/Apache-2.0/BSD许可证组合，确保无GPL传染风险，适合商业使用。

### 核心价值主张

| 维度 | 说明 |
|---|---|
| **零商业侵权** | 全部依赖采用MIT/Apache-2.0/BSD许可证，无GPL传染风险 |
| **本地部署** | 单文件.exe安装，无需Docker、无需Python环境、无需Node.js运行时 |
| **云端AI** | 用户配置自己的API Key，本地加密存储，无第三方代理 |
| **无限画布** | 所有资产（图片/视频/音频/文本/分镜）在画布上可视化管理 |
| **主Agent控子Agent** | 1个编排器拆解任务→5个专业子Agent并行/串行执行 |

## 核心组件

### 桌面框架层

**Tauri 2.x (Rust)**
- 比Electron小约90%，提供轻量级桌面应用框架
- 支持原生IPC通信、系统托盘、自动更新功能
- 使用Rust后端，提供更好的性能和安全性

**WebView2 (Windows内置)**
- Windows 10+预装，无需额外依赖
- 提供现代Web技术的桌面应用容器

### 前端组件

**React 18 + TypeScript 5.x**
- 成熟的前端生态，提供类型安全保障
- 支持现代化JavaScript特性

**Vite构建工具**
- 极速HMR（热模块替换），提升开发体验
- 优化的构建性能

**UI框架与组件库**
- @xyflow/react（React Flow）- 行业标准无限画布
- shadcn/ui + Radix - 无运行时依赖的UI组件
- Tailwind CSS - 原子化CSS框架
- Framer Motion - 声明式动画库

### 后端（Rust）

**核心运行时**
- axum - 高性能异步HTTP框架
- tokio - Rust异步运行时标准
- serde系列 - JSON序列化标准

**加密与安全**
- ring + aead - AES-256-GCM加密API Key
- Windows DPAPI加持

**数据库与插件**
- rusqlite - 嵌入式数据库
- wasmtime - WASM插件运行时

### 原生模块

**媒体处理**
- ffmpeg-sidecar - 自动下载管理ffmpeg二进制
- image-rs - Rust原生图像编解码
- symphonia - Rust原生音频解码（MPL-2.0）

**语音识别**
- whisper-rs - 本地语音转文字

## 详细组件分析

### Agent体系（核心设计）

#### 分层架构

```
┌─────────────────────────────────────────────┐
│  flowerage-orchestrator (主Agent)           │
│  角色：总编排器                               │
│  职责：理解用户意图 → 拆解任务 → 派发子Agent   │
│       → 汇总结果 → 更新画布                    │
│  模式：primary                                │
│  步数预算：400                                │
│  工具集：任务拆解 / 画布读写 / Memory / 派发    │
└──────┬──────┬──────┬──────┬──────────────────┘
       │      │      │      │
       ▼      ▼      ▼      ▼
┌──────┐ ┌────┐ ┌────┐ ┌────┐ ┌────────┐
│image │ │vid │ │spe │ │mus │ │editing │
│Agent │ │Agent│ │Agent│ │Agent│ │Agent   │
│      │ │    │ │    │ │    │ │        │
│ 200  │ │200 │ │200 │ │200 │ │ 200    │ ← 步数预算
└──────┘ └────┘ └────┘ └────┘ └────────┘
```

#### Agent详细定义

| Agent ID | 角色 | 核心能力 | 步数预算 | MCP工具数 |
|---|---|---|---|---|
| `flowerage-orchestrator` | 总编排器 | 意图识别→任务拆解→派发→汇总→画布同步 | 400 | 8 |
| `image-agent` | 图像专家 | T2I/I2I/角色一致性/多模型路由/批量生成 | 200 | 6 |
| `video-agent` | 视频专家 | T2V/I2V/多模态视频/运动控制/数字人 | 200 | 6 |
| `speech-agent` | 语音专家 | TTS/声音克隆/多角色对话/情绪控制 | 200 | 5 |
| `music-agent` | 音乐专家 | BGM/人声歌曲/翻唱/歌词创作 | 200 | 5 |
| `editing-agent` | 后期专家 | 片段合并/转场/唇形同步/BGM混音/MV流水线 | 200 | 8 |

#### 主Agent编排流程

```
Stage 1: 意图理解
  ├── 解析用户输入
  ├── 识别任务类型 (单模态/多模态/全流程)
  └── 输出：任务拆解计划

Stage 2: 并行派发
  ├── 无依赖的Agent → 并行执行（如 image + music 同时生成）
  ├── 有依赖的Agent → 串行执行（如 image 输出 → video 输入）
  └── 输出：各子Agent执行结果

Stage 3: 汇总与画布同步
  ├── 校验所有子Agent输出
  ├── 调用Canvas API注册节点
  ├── 建立sourceNodeId资产关系链
  └── 输出：用户可读的总结 + 画布更新
```

### 无限画布设计

基于@xyflow/react（React Flow）的无限画布，支持：

- **无限缩放**：0.1x ~ 5x，鼠标滚轮
- **拖拽布局**：自由拖拽节点
- **连线关系**：节点间有向边，表达资产依赖
- **分组节点**：Group Node收纳相关资产
- **小地图**：MiniMap全局导航
- **对齐吸附**：拖拽自动吸附对齐

#### 节点类型

| 节点类型 | 图标 | 功能 | 数据承载 |
|---|---|---|---|
| **ProjectNode** | 📁 | 项目根节点 | 项目名称/描述/创建时间 |
| **TextNode** | 📝 | 文本/脚本/创意 | Markdown内容 |
| **ImageNode** | 🖼️ | 图像资产 | 缩略图+提示词+模型+尺寸 |
| **VideoNode** | 🎬 | 视频资产 | 预览帧+提示词+时长+分辨率 |
| **AudioNode** | 🎵 | 音频资产 | 波形+时长+情绪标签 |
| **StoryboardNode** | 🎞️ | 分镜节点 | 镜头号+描述+时长+转场 |
| **TaskNode** | ⚙️ | Agent任务节点 | 任务状态+进度+Agent日志 |
| **GroupNode** | 📦 | 分组容器 | 子节点集合 |

## 性能考虑

### 技术选型优势

1. **Tauri替代Electron**
   - 体积减少约90%（从150MB缩减到60MB）
   - 性能显著提升，内存占用更低
   - 安全性增强，原生系统集成

2. **Rust后端优势**
   - 零成本抽象，接近C/C++的性能
   - 内存安全保证，无空指针和缓冲区溢出
   - 异步运行时tokio提供高并发处理能力

3. **WASM插件系统**
   - 沙箱隔离，比Python Cython .pyd更安全
   - 快速热加载，支持动态扩展
   - 跨平台兼容性

### 安装与运行时优化

- **零环境依赖**：无需Docker、Python、Node.js
- **自动更新**：增量更新机制，减少下载量
- **本地API Key**：用户自有密钥，避免中间代理
- **按需下载**：ffmpeg首次启动时自动下载

## 故障排除指南

### 常见问题与解决方案

**问题1：安装包无法运行**
- 检查Windows版本是否满足要求（Windows 10+）
- 确认系统已安装WebView2组件
- 重新下载安装包，确保完整性

**问题2：API Key无法保存**
- 检查Key Vault加密功能是否正常
- 确认Windows DPAPI服务可用
- 重启应用后重试

**问题3：画布节点无法显示**
- 检查Agent运行状态
- 确认Canvas同步功能正常
- 清理缓存后重试

**问题4：媒体处理失败**
- 检查ffmpeg二进制文件完整性
- 确认网络连接正常
- 查看日志文件获取详细错误信息
